uproot_custom.backend module¶

uproot_custom.backend.get_backend() → Literal['cpp', 'python', 'forth', 'detree'][source]¶

Return the current reader backend.

The backend is resolved in the following order of priority: explicitly set value via set_backend() > UPROOT_CUSTOM_READER_BACKEND environment variable > default “cpp”.

Returns:

The current reader backend (“cpp”, “python”, “forth”, or “detree”).

Raises:

ValueError – If the UPROOT_CUSTOM_READER_BACKEND environment variable is set to an unrecognized value.

uproot_custom.backend.set_backend(backend: Literal['cpp', 'python', 'forth', 'detree']) → None[source]¶

Set the current reader backend.

This overrides the UPROOT_CUSTOM_READER_BACKEND environment variable and the default “cpp”.

Parameters:

backend – The reader backend to use. Must be one of “cpp”, “python”, “forth”, or “detree”.

Raises:

ValueError – If backend is not a recognized reader backend.

uproot_custom.backend.use_backend(backend: Literal['cpp', 'python', 'forth', 'detree'])[source]¶

Context manager to temporarily switch the reader backend.

The original backend is restored when exiting the with block.

Example:

import uproot_custom as uc

with uc.use_backend("python"):
    branch.array()
Parameters:

backend – The reader backend to use within the context. Must be one of “cpp”, “python”, “forth”, or “detree”.

Raises:

ValueError – If backend is not a recognized reader backend.

uproot_custom.interpretation module¶

The uproot plumbing the AsCustom interpretation needs, and nothing else.

An uproot Interpretation has to answer five questions: does this branch match (match_branch), what is its C++ type name, how is it cached, how are the per-basket arrays joined, and what awkward form does it produce. Answering them means reading the branch’s streamer info and building a factory – none of which depends on how the bytes are then decoded.

AsCustom keeps that plumbing and delegates the byte-level read to the reader backend selected by uproot_custom.backend:

  • cpp – the pybind11 readers in uproot_custom.cpp (the default);

  • python – the pure-Python readers in uproot_custom.python;

  • forth – the experimental Forth readers in uproot_custom._forth;

  • detree – declarative readers in uproot_custom.detree, compiled to a detree-vm module and executed on a Detree machine.

A factory is the same on every backend: it decides which reader to build and how the raw data becomes an awkward array. Only the byte-level reader differs, so a branch must produce the same array whichever backend runs it.

Reads objects stored via ROOT’s read_object_any protocol.

This handles both: - True pointers (kObjectP=64, kAnyP=69): full read_object_any with null/reference support - Object headers (kNewClassTag + classname before object data)

Binary format (read_object_any):
  1. bcnt (uint32) — if kByteCountMask set: versioned, then read tag (uint32)

    otherwise: unversioned, tag = bcnt

  2. tag: - tag == 0: null pointer - tag & kClassMask == 0 (nonzero): reference to previously-read object (skip bytes) - tag == kNewClassTag: null-terminated classname + object data - tag & kClassMask != 0: reference to known class, new object data

uproot_custom.claim(path: str | Iterable[str]) → None[source]¶

Claim branches for Uproot-custom to interpret.

A claimed branch is read by AsCustom instead of by Uproot’s own interpretations. Each path is an object-path in the form branch.object_path reports it; the paths are regularized here, so the trailing ;N cycle number may be kept or dropped.

Claim every branch before its interpretation is first computed. Uproot caches that per branch object, so a claim made after branch.array(), tree.arrays() or tree.show() has no effect on that file object.

Parameters:

path – one object-path, or an iterable of them.
