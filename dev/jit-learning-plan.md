# Reader JIT 学习计划

```{important}
**目的：** 通过从零重写一遍 reader 虚拟机，理解寄存器机、字节码编码、调用约定与
分派成本。参考实现是 `uproot_custom/readers/jit/`，规格是 `dev/isa.md`。

**用法：** 每个阶段先自己写完并通过验收，再看参考实现并填最后的“差异记录”。
这份文件可以随手改，勾选框与表格就是进度条。
```

## 0. 三条规则

1. **先写后读。** 每个阶段自己写完、跑过验收测试，再打开参考实现 diff 一次。提前读
   `jit/vm.py`（777 行）会拿走推导过程——那是这个练习唯一有价值的部分。
2. **不 import 现有包。** 在新的目录或新的 git worktree 里建 `myvm/`，自己写
   `isa.py`、`module.py`、`builder.py`、`vm.py`。一旦 import 了
   `uproot_custom.readers.jit`，学习价值减半。
3. **先写验收测试。** 虚拟机没有编译器兜底：错了不会报错，只是从差一个字节的位置
   读出看起来合理的垃圾。测试是唯一的反馈信号。

## 1. 建议骨架

| 文件 | 内容 | 何时扩充 |
|---|---|---|
| `myvm/isa.py` | opcode 常量、typecode、buffer kind | 阶段 0 |
| `myvm/module.py` | 指令、函数、buffer 声明、编码 | 阶段 1 |
| `myvm/builder.py` | 汇编器：label、寄存器、回填 | 阶段 2 |
| `myvm/vm.py` | 执行器 | 阶段 0 起 |
| `tests/test_vm_*.py` | 验收测试 | 每阶段 |

四个源文件只加不删，这样任何时刻都有一个能跑的版本。

## 2. 阶段

### 阶段 0 — 最小可用 VM（2–3 小时）

- [ ] 完成并自测

**学：** 指令的表示、分派方式、寄存器窗口。

**做：** 只实现 `CONST`、`ADD`、`BUF_APPEND`、`RET`。手搓一个 4 条指令的模块，
跑出 `[3]`。

**必做实验：** 先用一串 `if/elif` 写分派，改成 `dict[op] -> handler`，用 `timeit`
比。结论会反直觉：分支少时 `if/elif` 更快，指令超过约 10 条 dict 才赢。这就是 VM
的核心成本模型——每条指令一次间接跳转。

**验收：** 加法、就地常量、越界寄存器三个测试。

**坑：** 把 opcode 写成 `str` 方便调试，后面一定会后悔。用 `IntEnum`。

### 阶段 1 — 指令编码与模块格式（2–3 小时）

- [ ] 完成并自测

**学：** 定长指令、立即数字段、canonical 序列化、内容哈希当缓存键、版本字段。

**做：** `Ins` 用定长结构（4 个单字节字段 + 2 个 32 位），写 `to_bytes()` 与
`to_dict()`/`from_dict()`。

**必做实验：** 同一棵树编译两次，断言字节完全相同；再打乱构造顺序，看是否相同（不
会——寄存器分配顺序变了）。由此自己推出“确定性 = 固定遍历顺序”。

**验收：** 往返测试、确定性测试、`isa_major` 不匹配必须被拒绝。

**坑：** `hash(obj)`/`id(obj)` 进模块（不可复现）；依赖 dict 顺序（意外可复现，
但别依赖）。

### 阶段 2 — 汇编器与 label 回填（3–4 小时）

- [ ] 完成并自测

**学：** 两遍汇编、前向引用、label 到绝对索引的解析。

**做：** `label()`/`mark()`/`jmp()`/`jz()`，`finish()` 时统一 patch。把
`for i in range(n): body` 手工 lowering 成 `CONST i,0; BR_GE_S i,n,end; body;
ADD i,i,1; JMP loop`。

**验收：** 用 builder 拼出 `(a+b)*2` 与一个计数循环，断言结果。

**进阶：** 参考实现的寄存器只增不复用（`reg_count` 能到 45）。自己设计一个“作用域
结束即释放”的分配器，量一下降到多少。这是寄存器分配问题的最小形态。

### 阶段 3 — 流模型与边界检查（3–4 小时）

- [ ] 完成并自测

**学：** 游标模型、大端解码、越界语义、事件循环归谁管。

**做：** `SREAD`（含宽度与符号扩展）、`SKIP`、`CURSOR`、`SET_CURSOR`；每次访问
先检查 `cursor + n <= len(data)`。

**必做实验：** 故意在每个事件开始时把游标归零，拿一个多 event 的真实 basket 跑，
看它怎么炸。参考实现第一版就踩了这个坑：entry offset 是累加的，游标必须跨事件
连续。故意制造再修，比读文档记得牢。

**验收：** 从 `tests/data/test_primitive.root` 的 `m_int` basket 读出正确数组。

**坑：** NumPy 2 对越界赋值抛 `OverflowError`。VM 必须自己定义截断语义（掩码 +
符号扩展），否则 `int8` 存 `255` 直接报错——这不是“实现细节”，而是“虚拟机定义了
整数语义”。

### 阶段 4 — 调用约定与帧（3–4 小时）

- [ ] 完成并自测

**学：** 帧栈、返回地址、参数与返回寄存器、递归上限。

**做：** `CALL rd, FUNC, ra` 把 `ra` 放进被调函数的 `r0`，`RET ra` 回填调用者的
`rd`。每帧有独立寄存器窗口，不共享。

**必做实验：** 先用手写 Python 递归实现 `CALL`，再改成显式帧栈。前者在一千层左右
撞 Python 的递归上限——这直接说明为什么真实 VM 要自己管栈、自己设上限。

**验收：** 一个自己调自己的模块，断言抛出自定义的 `StackOverflow`，而不是 Python
的 `RecursionError`。

### 阶段 5 — 值模型：宽度、符号、浮点（2–3 小时）

- [ ] 完成并自测

**学：** 寄存器不携带类型；整数环绕；浮点只搬位模式。

**做：** `SEXT*`/`ZEXT*`、有符号除余（向零截断）、`SHL`/`SHR`，以及写入 buffer
时的截断与重解释。

**必做实验：** 把 `float32` 的四个字节当 `uint32` 读进寄存器，再按位模式写回
`float32` buffer，断言得到 `3.5`。你会发现：VM 不需要浮点算术，只需要浮点搬运。

**验收：** `int8` 存 `-1`、`2^63` 环绕成负数、`float32` 往返。

### 阶段 6 — 粗粒度指令与性能模型（3–4 小时）

- [ ] 完成并自测

**学：** 分派成本与每元素成本的区别；可增长 buffer。

**做：** `READ_BULK buf, tc, n`，内部用 `np.frombuffer(..., dtype=">u4", count=n)`
一次拷完；`BUF_APPEND_OFFSET`。

**必做实验：** 一千个 `uint32`，分别用“循环 `SREAD` + `BUF_APPEND`”和一条
`READ_BULK` 跑，用 `timeit` 量。差距大约 **50–100 倍**。这条实验比任何文章都能
说明“VM 的性能由分派次数决定”。

**验收：** 两者结果一致；顺带确认 `np.append` 是 O(n²)，必须几何扩容。

### 阶段 7 — 前端：先写 emitter，别写 AST（4–6 小时）

- [ ] 完成并自测

**学：** 从后端视角看 lowered form；默认方法由前端在编译期展开。

**做：** 挑三个构造（标量、`TString`、`std::vector`），每个写一个“类 → 函数”的
emit 函数。不要做 AST 分析——那是在 VM 稳定之前给自己叠难度。参考实现走的就是
手写 emitter 路线：`nodes/primitive.py` 只有 40 行。

**必做实验：** 把“默认 `read_many` 是一个循环”这件事交给前端统一生成，而不是每个
节点重写；体会默认方法在编译期被内联进每个节点。

**验收：** 编译并读通一个真实分支。

### 阶段 8 — 对象图：字符串与引用（4–6 小时）

- [ ] 完成并自测

**学：** 寄存器机怎么表示值类型（arena + id）、interning、`-1` 哨兵、引用表与对象
身份、类名去重。这是整个 VM 里最像“有堆的语言运行时”的一段。

**做：** `SREAD_CSTR`（读到 NUL，intern 成 id）、`STR_EQ`/`STR_STORE`/`STR_LOAD`、
`REF_SET_OBJ`/`REF_GET_OBJ`/`REF_COUNT`。

**验收：** 指针分支与 Python 后端逐元素一致。

**坑（参考实现踩过的两个，建议先自己踩一次再对照）：**

- 一个含义为“不带版本”的布尔标志，配 `JZ` 还是 `JNZ` 写反了不会报错，只是从错误
  的偏移读 tag，最后表现为“游标跑到 `0xC0000001`”。
- state 的初值 `-1` 被框架默认成 `0`，于是“尚无类名”变成了合法字符串 id `0`（正好
  是某条消息模板）。**哨兵值必须显式初始化。**

### 阶段 9 — 验证器与差分测试（2–3 小时）

- [ ] 完成并自测

**学：** 为什么要在执行前静态检查；oracle 测试。

**做：** 检查寄存器、跳转目标、各类 id 引用；再拿一个成熟实现当 oracle，做逐分支
差分。

**必做实验：** 故意生成一条跳到函数外的指令，先在没有验证器的情况下跑，记下现象
（通常是莫名其妙的 `IndexError`）；加上验证器再看错误信息。这就是“VM 的错误必须
可定位”的价值。

**验收：** 差分测试通过；错误信息里带得到函数名、指令下标与游标。

### 阶段 10 — 可选进阶（选一个）

- [ ] 完成并自测

- **线程化分派**：Python 里已经是 `dispatch[op](self, ins)`；到这里读 C 的
  computed goto，理解它为什么比 `switch` 快。
- **超指令融合**：把 `SREAD + BUF_APPEND` 合成 `READ_APPEND`，量收益。
- **寄存器存储**：把寄存器从 list 换成数组或局部变量，量收益（通常比换分派方式
  收益更大）。
- **同一份字节码写一个 C++ VM**，用 Python VM 当 oracle 做差分——这是“字节码与
  后端无关”的实证。
